# sunmind 项目拷打篇（面试官深挖 · 追命连环问）

> "拷打" = 面试官基于你的简历 / 介绍逐层往下追问，专挑你没做、没想清楚、没数据的地方打。本文按 **考官原话 → 他在挖什么 → 参考答法 → 说错会挂的点** 组织，目的是被问到时不被打穿。

---

## 拷打总原则

1. **没做的要诚实**：直接说"这个我没做 / 没测"，然后立刻补"如果做我会怎么做"。硬撑比承认更减分。
2. **凡结论必须带代价**：任何"我用 XX 优化"都要能补一句"代价是 YY"，否则显得背模板。
3. **参数必须有出处**：阈值 / 权重被问"怎么定的"，答"拍脑袋"= 挂；答"调出来的 / 有实验"= 加分。

## A 类 · 价值与创新（先质疑你这个项目值不值得做）

**A1. "RAG 现在开源方案一堆，你做的跟直接调 LangChain + 向量库有什么区别？你的技术含量在哪？"**
- 挖什么：你是不是只会调库，有没有真正的工程 / 算法设计。
- 参考答：承认单点技术不新，价值在**工程整合 + 三个原创设计**：①父子块解耦召回精度与上下文长度；②正 / 负画像分离的 DPU 闭环（负画像只增不减、失败回滚）；③全链路降级（混合检索→稠密、rerank→RRF）保证可用性。这些不是抄的，是踩坑踩出来的。
- 挂点：答"我觉得 LangChain 不好用所以我重写"——无技术依据，显傲慢。

**A2. "你的记忆 / 画像系统说得好听，到底把回答质量提升了多少？有数字吗？"**
- 挖什么：你有没有评测意识，还是自嗨。
- 参考答：诚实说"上线前没有系统评测，这是我最大短板"。然后补"如果做，我会用 RAGAS 四维（faithfulness / answer relevancy / context relevancy / answer correctness）做有画像 vs 无画像的 AB，看个性化问题（如'我上次要的 xx'）的命中率"。
- 挂点：编一个假数字，被追问"样本量多少 / 怎么抽样"直接穿帮。

**A3. "这项目有真实用户吗？没流量你谈高并发、谈画像更新，是不是纸上谈兵？"**
- 挖什么：是不是玩具项目、有没有真实约束驱动。
- 参考答：定位清楚——这是学习 / 求职项目，规模是单机 demo；但设计时按"有并发、多用户"的约束来做（连接池、隔离、降级），而不是写死单用户脚本。真实流量问题我承认没有，所以聊高并发时会明确区分"已做"和"计划做"。
- 挂点：假装有生产流量。

## B 类 · 评测与数据（最狠的一刀，90% 挂在这）

**B1. "你说父子块比单一分块好，召回率提升多少？实验呢？消融做过吗？"**
- 挖什么：结论有没有实验支撑。
- 参考答：诚实"没跑正式消融"。给方法论：用同一评测集（50 条真实问题 + 人工标注正确答案所在块），对比「单一大块 / 纯小块 / 父子块」的 hit@k 和答案端到端准确率。父子块的设计动机是解耦（小块召回准 + 大块上下文全），这是社区已验证的思路，但我自己的数据还没有，是要补的。
- 挂点：说"大家都这么说所以对"，无数据还硬。

**B2. "token 阈值 1000、类型权重 0.7/1.3/1.0/1.2、衰减 0.995，这些数怎么来的？拍脑袋吗？"**
- 挖什么：参数是否有依据。
- 参考答：分两类——0.995 衰减（每小时 0.5%）是"记忆随时间指数遗忘"的先验；语义记忆权重高是因为"稳定事实比一次性事件更值得召回"，这些是**设计直觉，不是网格搜索出来的**。诚实承认"权重是拍脑袋，但留了配置化，可以离线调"；token 阈值 1000 是刻意保持不变的（控制触发频率，避免每轮都打 LLM 提取）。
- 挂点：全部说"我精心调出来的"却说不清怎么调、调了什么。

**B3. "降级之后质量掉多少你测过吗？你说可用性优先，那精度优先的场景怎么办？"**
- 挖什么：降级策略是不是想当然。
- 参考答：没量化测过。设计原则是"先可用后精准"——外部依赖失败时先给一个基于稠密 / RRF 的可用答案，好过 500。如果要精度优先，可以加"降级标记"让前端提示"当前为降级结果"，或对高价值场景禁用降级、直接报错重试。
- 挂点：说"降级了也一样准"，无视降级必然损失精度。

## C 类 · 一致性与可靠性（深挖，容易暴露半吊子）

**C1. "跨 PG + Milvus 用补偿回滚，那回滚本身也失败了怎么办？你还是有半提交状态啊。"**
- 挖什么：对分布式一致性理解多深、有没有想过补偿失败。
- 参考答：承认补偿回滚只解决"单点失败"，不解决"回滚也失败"的双故障。更稳做法：①"状态机 + 对账任务"——写 PG 的 summary_id 是"意图标记"，后台定期对账 PG 与 Milvus 是否一致，不一致重放或清理；②最终一致允许短暂不一致，但要有自愈。这是从"补偿"到"可恢复"的进阶。
- 挂点：说"不会失败"或"我加个 try 就稳了"。

**C2. "你全局 agent 单例只在首次创建时绑 checkpointer，每请求新建的 checkpointer 又被丢，多轮状态到底串不串？"**
- 挖什么：你有没有真读懂自己的并发代码。
- 参考答：诚实说这是隐患——agent 图本身无状态可安全共享，但 checkpointer 生命周期和单例不匹配，高并发 / 多请求下可能用到已关闭的连接。修法：checkpointer 也做成全局单例，按 thread_id 分区隔离是天然安全的。
- 挂点：被指出后还嘴硬"我测过没问题"。

**C3. "画像缓存 TTL 1 小时，这 1 小时内用户画像更新了，你注入的是旧画像，不一致怎么办？"**
- 挖什么：缓存一致性的经典追问。
- 参考答：用"写后更新 / 失效"——画像更新时（`update_user_profile`）同步 setex 覆盖缓存（代码里已做），正常路径是新值；TTL 只是防脏数据兜底。极端情况（更新和读并发）有窗口期读到旧值，对画像这种"软偏好"影响可接受；负画像同理且只增不减更稳。
- 挂点：说"我不用缓存了"（因噎废食）或"不会不一致"。

## D 类 · 安全与多租户

**D1. "你 API key 都明文放在环境变量里，安全怎么做？多租户下 Redis 缓存 key 隔离了吗？"**
- 挖什么：安全意识 + 多租户是否贯彻到底。
- 参考答：key 用环境变量 / 密钥管理服务（vault / 云 KMS）托管，不硬编码、不进 git（现已在 .env 且不入库）。Redis 画像 key 是 `user_profile:{user_id}` 带 user_id 天然隔离；但 checkpoint `thread_id=user_id` 没有会话级隔离，是缺口。
- 挂点：说"本地 demo 不用考虑安全"。

**D2. "Milvus 你 partition key 隔离了，但 Redis 里 checkpoint 用 thread_id=user_id，两个并发会话不会互相覆盖吗？"**
- 挖什么：隔离是否真正端到端。
- 参考答：诚实——当前把 user_id 当 thread_id，同一用户多会话共用一个 checkpoint，会互相覆盖 / 串历史，这是明确缺口。修法：thread_id 改成 `user_id:session_id`，前端 / 后端生成会话 id，checkpoint 和 raw_conversations 都用它，做到会话级隔离。
- 挂点：掩盖这个已知缺口。

## E 类 · 性能量化

**E1. "一个请求全链路要多久？embedding 1s + rerank 1s + LLM 好几秒，你怎么跟用户交代？"**
- 挖什么：有没有延迟意识、怎么优化。
- 参考答：分阶段——首 token 延迟靠流式（用户先看到字）；全量延迟靠：①检索并行（已做）、②embedding / 检索结果缓存、③rerank 只对 top-N 做、④LLM 选小模型 / 流式。诚实报量级："冷请求端到端约 3~5s，外部 API 占大头"。
- 挂点：说不出各环节耗时，说明没 profile 过。

**E2. "压测过吗？QPS 多少？瓶颈在哪？"**
- 挖什么：量化能力。
- 参考答：没正式压测（诚实）。如果测，瓶颈大概率在**外部 LLM 调用的串行等待 + 每请求建 Redis 连接**，而不是本地向量库。这正是高并发改造计划里的 P0 项。给出"用 Locust 打流式接口、监控 P99 和外部 429"的方法。
- 挂点：报一个没跑过的 QPS 数字。

## F 类 · 设计优先级与前瞻

**F1. "你说缺限流缺队列，为什么不一开始就做？是不是设计时就没想过高并发？"**
- 挖什么：设计前瞻性 + 迭代意识。
- 参考答：分阶段设计是刻意为之——先打通"功能闭环"（检索 / 记忆 / 画像可用），再按"成本收益"补非功能项（限流 / 队列 / 多进程）。过度设计会把早期 demo 做重；但我会在评审里提前把高并发项列为 backlog，而不是事后才发现。既承认优先级选择，又显得有规划。
- 挂点：说"没想过"，或反过来"我一开始就全做了"（与现状矛盾）。

## 终极一页纸：拷打防御清单

- 凡"优化 / 更好" → 必答"**代价 + 有没有数据**"
- 凡"参数 / 阈值" → 必答"**先验 or 调参，留了配置**"
- 凡"一致性 / 并发" → 必答"**已做 + 已知缺口 + 修法**"
- 凡"安全 / 隔离" → 必答"**存储层做了，Redis 会话隔离是缺口**"
- 凡"没做 / 没测" → 先认，再给"**我会怎么做**"
